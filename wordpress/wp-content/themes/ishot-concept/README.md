# iShot Concept (WordPress block theme)

Presentation only: bookings, services and client data live in the `ishot-booking` plugin, so switching themes never loses data.

## One token source

`npm run sync:ds` (also run before `dev` and `build`) generates everything below from `design-system/`. **Never edit the generated files by hand.**

| File | Source |
|---|---|
| `theme.json` | `theme.base.json` (hand-kept: settings switches and element styles) + presets from `design-system/tokens.json` |
| `assets/css/tokens.css`, `assets/css/bundle.css` | The design system's CSS, unchanged except that the Google Fonts `@import` is removed, so `fo-` markup renders exactly as in the React prototype |
| `assets/fonts/*.woff2` | Latin subsets of Oswald (500/600/700) and Space Grotesk (400/500/700) from `@fontsource`, self-hosted |

Generated presets:
- **Palette:** semantic colours only (`paper`, `ink`, `band`, `accent`, `highlight`, …). Their values are `var(--token)`, so the Night theme (`data-theme="dark"`) re-colours anything the editor applies.
- **Font sizes:** one per type style. Each style's usage note gives its sizes, such as "(60 / 48 / 36)". Styles with more than one size become fluid between 375px and 1280px.
- **Spacing:** the `space-*` scale. **Layout:** content 720px, wide 1280px.

`assets/css/theme.css` is hand-written. It adapts core blocks: square buttons and images, the outline button, form controls, hairline separators, and gutters that grow with the viewport. It may use only tokens; `npm run lint:tokens` rejects raw colours and durations.

The owner cannot pick custom colours, sizes, gradients, duotones or radii. Every editor choice is a design-system token.

## Requires plugins

The theme is presentation only and needs two companion plugins from this repository:

- **`ishot-booking`**: bookings, services, content types and client data.
- **`ishot-blocks`**: the reusable content blocks (hero, founder, services and so on). They live in the plugin, not the theme, so page content keeps rendering after a theme change. `ishot-blocks` itself requires `ishot-booking` (`Requires Plugins` header, WordPress 6.5+).

Without the companion plugins the theme prints its frame (header, menu sheet, footer) without the plugin parts (social links, contact details, the sample-content notice); the plugin blocks print nothing and the theme calls plugin classes behind `class_exists`. The admin notice for missing plugins is still planned.

Theme tests (`tests/`) run from the `ishot-blocks` PHPUnit config, which loads both plugins and activates this theme: `npm run test:theme`.

## Status

- **3a done:** scaffold, generated `theme.json`, self-hosted and preloaded fonts, core overrides, editor styles.
- **Stage 1 (3b–3c), in progress:** header and footer parts (Tasks 1.2, 1.3); base templates `index`, `page`, `single`, `404`, `search`, the `page-title` pattern and the `ishot/notice` block (Task 1.4). Every template is header part + `<main id="main" tabindex="-1">` + footer part inside one `.fo-root.ish-app` group, as the prototype's `App.jsx`. `tabindex` is added server-side by the theme's one `render_block_core/group` filter (`inc/groups.php`). The document title separator is `·` ("Page not found · iShot Concept").
- **Editor canvas:** `assets/css/editor-root.css` (generated by `sync:ds` from the bundle's `.fo-root` rules) is loaded as an editor style only, so a template part opened on its own in the Site Editor gets the same border-box sizing as on the front end.
- **Later stages:** page bodies, the remaining `ishot/*` blocks, more patterns and template locking.

## Development

The theme is mapped into wp-env (`.wp-env.json`) and active on the dev site. `wordpress/dev/style-check.php` creates a "Style check" page of core blocks for eyeballing the overrides.

Dev-only fixtures (`wp-env run cli wp eval-file wp-content/ishot-dev/<file>`). Both refuse to write unless every guard in `IShot\Booking\Dev\DevGuard` passes (environment type local/development, `ISHOT_DEV_FIXTURES === true` from `.wp-env.json` `env.development.config`, a localhost/127.0.0.1/.local/.test host), and neither overwrites owner content:

- `studio-details-dev.php`: fills empty Studio details from the prototype (marked unconfirmed).
- `page-shells-dev.php`: creates published, title-only page shells for `about`, `services`, `portfolio`, `creative-direction`, `journal`, `contact`, `book` and `account`, plus the journal post shell `what-to-wear-for-your-portrait-session`, each with `content_status` = placeholder (the "Sample content." notice shows). A page or post with the same slug is left alone. It also switches the wp-env default permalink structure `/%postname%/` to `/journal/%postname%/` (Task 3.1 sets this for real); any other structure is kept. Run it again at any time: it changes nothing the second time.
